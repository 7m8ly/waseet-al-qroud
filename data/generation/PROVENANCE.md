# How the synthetic data was produced (disclosure)

| Part | How | Tool |
|---|---|---|
| Scenario table, all numbers, intended outcomes (cases_spec.py) | Designed by hand against the rulebook; monthly wallet totals and counts planned so medians and data depth are known in advance | Team, with Claude (AI assistant) drafting the table; reviewed by the team |
| Wallet transactions | Generated by `wallets_make.py` from the planned totals; fixed seed per case; reproducible byte for byte | Python script (no LLM) |
| Applicant names | Composed by script from first-name, father-name and family-name lists; unique across the whole dataset; not real persons | Python script (no LLM) |
| Activities, loan purposes, dialogues, adversarial messages | Written with Claude (AI assistant), expected values derived by hand from the text | Claude |
| Expected outcomes | The *planted intentions* in `cases_spec.py`, cross-checked by an independent calculator (`oracle.py`); worked arithmetic in `heldout/CALCULATIONS.md` | Hand + script |

Not used for this data: Groq, Gemini, OpenRouter or any other hosted model. The challenge guide suggests an LLM for text fields; here the text was written with Claude instead, and that is disclosed here and in `docs/MODELS.md`.
No real personal, customer, identity or transaction data was used or sent to any model.

Regenerate everything: `python data/build_cases.py && python data/build_fairness.py && python data/build_dialogues.py && python data/build_adversarial.py && python data/build_calculations.py && python data/cases_validate.py`
